# Spec

## Purpose

Предоставляет библиотекарям возможность управлять документами: добавлять новые документы, редактировать существующие и удалять документы из каталога.

## Requirements

### Requirement: Добавление нового документа
Система ДОЛЖНА позволять библиотекарю добавлять новый документ в каталог с указанием метаданных и загрузкой электронного файла.

#### Scenario: Успешное добавление документа
- **WHEN** библиотекарь заполняет обязательные поля (название, автор, год издания), выбирает файл и нажимает кнопку "Добавить"
- **THEN** система создает новый документ, сохраняет файл и отображает документ в каталоге

#### Scenario: Добавление с опциональными полями
- **WHEN** библиотекарь заполняет все поля (включая жанр, издательство, аннотацию) и загружает файл
- **THEN** система создает документ с полной информацией

#### Scenario: Добавление без обязательных полей
- **WHEN** библиотекарь пытается добавить документ без названия, автора или года издания
- **THEN** система отображает сообщение об ошибке и не создает документ

#### Scenario: Добавление с существующим автором
- **WHEN** библиотекарь выбирает существующего автора из списка автодополнения
- **THEN** система связывает документ с существующим автором без создания дубликата

### Requirement: Редактирование документа
Система ДОЛЖНА позволять библиотекарю изменять метаданные существующего документа.

#### Scenario: Успешное редактирование метаданных
- **WHEN** библиотекарь изменяет поля документа и нажимает кнопку "Сохранить"
- **THEN** система обновляет информацию о документе в каталоге

#### Scenario: Редактирование с удалением обязательных полей
- **WHEN** библиотекарь пытается очистить название, автора или год издания
- **THEN** система отображает сообщение об ошибке и не сохраняет изменения

#### Scenario: Редактирование авторов
- **WHEN** библиотекарь добавляет или удаляет авторов документа
- **THEN** система обновляет связи между документом и авторами

#### Scenario: Редактирование жанров
- **WHEN** библиотекарь изменяет список жанров документа
- **THEN** система обновляет связи между документом и жанрами

### Requirement: Замена электронного файла
Система ДОЛЖНА позволять библиотекарю заменить электронный файл документа.

#### Scenario: Успешная замена файла
- **WHEN** библиотекарь загружает новый файл для существующего документа
- **THEN** система заменяет старый файл новым и обновляет информацию о файле (формат, размер)

#### Scenario: Замена файла с изменением формата
- **WHEN** библиотекарь загружает файл в другом формате
- **THEN** система заменяет файл и обновляет формат в метаданных

### Requirement: Удаление документа
Система ДОЛЖНА позволять библиотекарю удалять документ с подтверждением операции.

#### Scenario: Успешное удаление с подтверждением
- **WHEN** библиотекарь нажимает кнопку "Удалить" и подтверждает удаление
- **THEN** система удаляет документ, файл и все связанные записи (авторы, жанры)

#### Scenario: Отмена удаления
- **WHEN** библиотекарь нажимает кнопку "Удалить" и отменяет подтверждение
- **THEN** система не выполняет удаление и документ остается в каталоге

#### Scenario: Каскадное удаление связей
- **WHEN** документ удаляется
- **THEN** система автоматически удаляет связи с авторами и жанрами

### Requirement: Валидация метаданных
Система ДОЛЖНА проверять корректность введенных метаданных при добавлении и редактировании документа.

#### Scenario: Проверка обязательных полей
- **WHEN** библиотекарь сохраняет документ без обязательных полей
- **THEN** система отображает список отсутствующих обязательных полей

#### Scenario: Проверка формата года
- **WHEN** библиотекарь вводит некорректный год издания
- **THEN** система отображает сообщение об ошибке формата

#### Scenario: Проверка наличия файла
- **WHEN** библиотекарь пытается добавить документ без выбора файла
- **THEN** система отображает сообщение о необходимости выбора файла

### Requirement: Стилизованная форма добавления документа
Система ДОЛЖНА отображать форму добавления документа с визуальной группировкой полей, разделителями секций и единообразными стилями согласно дизайн-системе.

#### Scenario: Группировка полей формы
- **WHEN** библиотекарь открывает форму добавления документа
- **THEN** поля формы логически сгруппированы: основные метаданные, дополнительные метаданные, жанры, файл

#### Scenario: Валидация с визуальной обратной связью
- **WHEN** библиотекарь пропускает обязательное поле
- **THEN** поле подсвечивается красной рамкой с поясняющим текстом ошибки

#### Scenario: Индикатор загрузки
- **WHEN** библиотекарь нажимает «Добавить» и данные отправляются на сервер
- **THEN** кнопка меняется на состояние загрузки (спиннер + текст «Загрузка...») и блокируется от повторного нажатия

### Requirement: Стилизованная форма редактирования документа
Система ДОЛЖНА отображать форму редактирования документа с тем же визуальным стилем, что и форма добавления, плюс отображение текущего файла.

#### Scenario: Отображение текущего файла
- **WHEN** библиотекарь открывает форму редактирования документа с загруженным файлом
- **THEN** в секции файла отображается текущее имя файла и кнопка замены

### Requirement: Карточка документа с визуальной иерархией
Система ДОЛЖНА отображать детальную информацию о документе с чёткой визуальной иерархией: название (h1), метаданные в структурированном блоке, действия в выделенной панели.

#### Scenario: Просмотр метаданных документа
- **WHEN** пользователь открывает карточку документа
- **THEN** метаданные отображаются в структурированных строках с иконками (автор, год, издательство, жанры, формат, размер)

#### Scenario: Панель действий
- **WHEN** пользователь просматривает карточку документа
- **THEN** действия (Читать, Скачать, Редактировать, Удалить) отображаются в стилизованной панели с иконками
