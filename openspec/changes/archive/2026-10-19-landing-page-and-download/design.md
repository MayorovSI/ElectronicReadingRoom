# Design

## Context

См. proposal.md — мотивация изменений.

Текущее состояние: маршрут `/` ведёт напрямую на `Catalog.razor`. Навигация библиотекаря в `MainLayout.razor` использует относительные пути `documents/add` и `genres` без ведущего `/` — Blazor не резолвит их корректно. Файлы отдаются через `FilesController.GetFile` без заголовка `Content-Disposition`, поэтому браузер отображает их вместо скачивания. Кнопка «Скачать» отсутствует.

## Goals / Non-Goals

**Goals:**
- Стартовая страница с выбором роли как точка входа
- Каталог на отдельном маршруте `/catalog`
- Работающая навигация для библиотекаря
- Возможность скачать файл документа на компьютер

**Non-Goals:**
- Аутентификация и авторизация — роль по-прежнему выбирается пользователем
- Изменение форматов файлов или механизма хранения
- Новый UI для загрузки файлов библиотекарем — уже реализован через multipart/form-data

## Decisions

### D1: Маршрутизация — `/` для landing, `/catalog` для каталога

`@page "/"` перемещается с `Catalog.razor` на новый `Landing.razor`. Каталог получает `@page "/catalog"`. NavLink в навигации обновляется на `href="/catalog"`.

Альтернатива: оставить `/` для каталога и сделать landing на `/start` — хуже для пользователя, который ожидает увидеть приветствие при входе.

### D2: Landing.razor — простой Blazor-компонент с двумя кнопками

Страница содержит заголовок «Электронный читальный зал» и две кнопки: «Читатель» и «Библиотекарь». При нажатии устанавливается `ModeService.SetMode(...)` и выполняется `Navigation.NavigateTo("/catalog")`. Никаких сложных анимаций или форм — минималистичная страница в стиле существующего UI (Bootstrap 5).

### D3: Скачивание — отдельный API-эндпоинт `/api/files/{id}/download`

Текущий `FilesController.GetFile` отдаёт файл для просмотра (inline). Добавляется новый метод `GetFileForDownload(int id)`, который:
1. Получает документ по ID → находит `DocumentFile.Path`
2. Определяет оригинальное расширение из `DocumentFile.Format`
3. Формирует `Content-Disposition: attachment; filename="<document-title>.<ext>"`
4. Отдаёт файл

Альтернатива: добавить query-параметр `?download=true` к существующему эндпоинту — менее RESTful, но проще. Выбран отдельный эндпоинт для чистоты API.

Клиент формирует ссылку: `<a href="/api/documents/{id}/download" download>` — браузер сам скачает файл.

### D4: Навигация — исправление NavLink и добавление «Сменить роль»

В `MainLayout.razor`:
- `href="documents/add"` → `href="/documents/add"`
- `href="genres"` → `href="/genres"`
- Добавить элемент «Сменить роль» → `href="/"`
- Каталог: `href=""` → `href="/catalog"`

### D5: Кнопка «Скачать» в DocumentDetails и DocumentViewer

В обеих страницах добавить кнопку `<a href="/api/documents/{id}/download" class="btn btn-outline-primary" download>Скачать</a>`. Кнопка видна в обоих режимах (читатель и библиотекарь). Скрыта, если `document.File is null`.

## Risks / Trade-offs

- [Пользователь может пропустить landing и перейти прямо на `/catalog`] → Каталог работает и без выбора роли (режим по умолчанию — Читатель), это допустимо
- [Нет защиты от прямого доступа к `/documents/add` в режиме читателя] → Существующее поведение: страница доступна, но ссылка в навигации скрыта. MVP не требует серверной авторизации
