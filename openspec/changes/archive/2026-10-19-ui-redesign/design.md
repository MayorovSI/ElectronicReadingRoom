# Design

## Context

Проект: Blazor WebAssembly (WASM) + ASP.NET Core 8, фронтенд на Blazor-компонентах с Bootstrap 5.3.3 (CDN).
Текущее состояние: 100% дефолтный Bootstrap без кастомной дизайн-системы. Единственный кастомный стиль — `.viewer-container { background-color: #f8f9fa }`.
CSS-переменные отсутствуют, шрифт — системный Helvetica/Arial. Имеются неиспользуемые scoped CSS-файлы от шаблона Blazor (sidebar).

Ограничения:
- Не меняем функциональность и API
- Bootstrap остаётся основой — кастомные стили накладываются поверх
- Blazor WASM — используем CSS-переменные, не CSS-in-JS/препроцессоры
- Изменения только в статических файлах и razor-компонентах

## Goals / Non-Goals

**Goals:**
- Создать единый источник стилей (`app.css`) с CSS-переменными (цвета, отступы, тени, радиусы, анимации)
- Подключить Google Fonts (Inter) для типографики
- Переработать визуальное оформление всех страниц с сохранением Bootstrap-разметки
- Добавить hover-эффекты, transition-анимации на интерактивных элементах
- Обеспечить адаптивность (mobile/tablet/desktop)
- Удалить неиспользуемые scoped CSS-файлы от шаблона

**Non-Goals:**
- Не меняем тёмную тему (mode switching — функциональный, не визуальный)
- Не добавляем JavaScript-анимации или библиотеки анимаций
- Не меняем структуру Razor-компонентов (только CSS-классы и инлайн-стили → классы)
- Не меняем серверную часть

## Decisions

### Decision 1: CSS-переменные в `:root` как дизайн-токены

**Выбор:** Определить все дизайн-токены как CSS custom properties в `:root` блока `app.css`.

**Альтернативы:**
- SCSS/LESS переменные: требуют препроцессора, невозможны в Blazor WASM без доп. сборки
- CSS-in-JS: не поддерживается в Blazor
- Отдельный JSON/YAML с токенами: избыточно для текущего масштаба, потребовал бы кодогенерации

**Палитра:**
```
Primary (синий):    #2563eb (акценты, кнопки, ссылки)
Accent (янтарный):  #f59e0b (режим библиотекаря, предупреждения)
Bg (фон):           #f8fafc (основной фон страниц)
Surface (карточки): #ffffff (фон карточек, форм)
Text primary:       #1e293b (основной текст)
Text secondary:     #64748b (второстепенный текст)
Success:            #10b981
Danger:             #ef4444
```

### Decision 2: Google Fonts Inter через `<link>` в `index.html`

**Выбор:** Подключить Inter (400, 500, 600, 700) из Google Fonts CDN как `<link>` в `<head>`.

**Альтернативы:**
- Локальный шрифт: требует лицензирования и хранения файлов
- Системный шрифт (текущий): не даёт желаемой эстетики

### Decision 3: Переход от инлайн-стилей к CSS-классам

**Выбор:** Заменить все `style=` атрибуты в razor-компонентах на CSS-классы в `app.css`.

**Обоснование:** Инлайн-стили затрудняют поддержку, не могут быть переопределены медиа-запросами и не используют дизайн-токены.

### Decision 4: Bootstrap остаётся основой, кастомные стили поверх

**Выбор:** Не удалять Bootstrap-классы из компонентов. Добавлять кастомные классы рядом с Bootstrap-классами для стилизации.

**Пример:** `<div class="card h-100 shadow-sm doc-card">` — Bootstrap обеспечивает раскладку, `doc-card` добавляет кастомные hover-эффекты, скругления и тени.

**Альтернативы:**
- Полный отказ от Bootstrap: слишком затратно, теряем responsive grid и компоненты
- Tailwind: требует смены всего подхода, нецелесообразно для Blazor

### Decision 5: Удаление неиспользуемых scoped CSS

**Выбор:** Удалить `MainLayout.razor.css`, `NavMenu.razor.css` и все сгенерированные scoped CSS-бандлы (`obj/`).

**Обоснование:** Эти файлы содержат стили sidebar из шаблона Blazor, который заменён на top navbar. Они всё ещё грузятся в браузер как `ElectronicReadingRoom.Client.styles.css`, создавая мёртвый CSS.

### Decision 6: Адаптивность через медиа-запросы + Bootstrap grid

**Выбор:** Использовать Bootstrap responsive utilities (`col-lg-*`, `col-md-*`) + собственные медиа-запросы в `app.css` для кастомных компонентов.

**Точки перелома:**
- Mobile: < 768px
- Tablet: 768–1199px
- Desktop: ≥ 1200px

## Risks / Trade-offs

- **[Риск] Конфликт с Bootstrap-специфичностью:** Кастомные стили могут не переопределить Bootstrap при равной специфичности → **Митигация:** Использовать селекторы на класс выше по специфичности (например, `.navbar.library-navbar` вместо `.navbar`)
- **[Риск] Поломка Blazor-рендеринга при изменении разметки:** Blazor WASM чувствителен к сложным биндингам (`@bind:after`) → **Митигация:** Не менять C#-код компонентов, только HTML-разметку и CSS-классы
- **[Риск] Увеличение размера CSS:** Добавление кастомных стилей увеличит `app.css` → **Митигация:** Минимизировать дублирование через CSS-переменные, не добавлять неиспользуемые утилиты
- **[Trade-off] Google Fonts — внешняя зависимость:** Медленная загрузка шрифта при плохом интернете → **Митигация:** Использовать `font-display: swap` и системный fallback

## Migration Plan

1. **Подготовка:** Добавить CSS-переменные в `app.css`, подключить Google Fonts в `index.html`, переопределить базовые стили Bootstrap через переменные
2. **Лендинг + навигация:** Переработать `Landing.razor` и `MainLayout.razor`
3. **Каталог:** Переработать `Catalog.razor`, добавить `.doc-card` класс
4. **Формы + детали:** Переработать `DocumentAdd.razor`, `DocumentEdit.razor`, `DocumentDetails.razor`
5. **Просмотрщик + жанры:** Переработать `DocumentViewer.razor`, `GenreManagement.razor`
6. **Очистка:** Удалить неиспользуемые scoped CSS, удалить инлайн-стили
7. **Финальная проверка:** Пройти все страницы в обоих режимах на desktop/tablet/mobile

Rollback: Откатить изменения в `app.css`, `index.html`, и razor-файлах через git. CSS-переменные не затрагивают логику — откат безопасен.
